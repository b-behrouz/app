# هم‌قدم — نسخهٔ مستقل محلی

`hamghadam-preview.html` خروجی مستقل و نهایی پروژه است. فونت‌ها، استایل، JavaScript، تصاویر و داده‌های لازم در خود فایل قرار دارند. استفادهٔ نهایی باید با دانلود فایل و دابل‌کلیک، بدون نصب یا وب‌سرور باشد. وابستگی‌های زیر فقط برای توسعه و آزمون هستند.

## ساخت قابل تکرار

ابزار توسعه: Python 3.10+ و Node.js 22+. بازکردن HTML به این ابزارها نیاز ندارد.

```sh
python3 scripts/build_preview.py
python3 scripts/check_project.py
node tests/test_center_server.cjs
```

ساخت فقط محتوای `src/app.js`، `src/style-*.css` و `src/index.template.html` را بدون بازنویسی بایت‌هایشان کنار هم می‌گذارد. همهٔ منابع لازم قبلاً داخل سورس جاسازی شده‌اند؛ build وابسته به شبکه نیست. HTML را دستی و جدا از سورس تغییر ندهید.

سورس React/TSX و تنظیمات build اولیه در اختیار این پروژه نبوده‌اند. `src/` نسخهٔ بازیابی‌شدهٔ runtime ضمیمه‌شده است. وضعیت دقیق و محدودیت‌ها در [docs/STATUS.md](docs/STATUS.md) ثبت شده است. ورودی اولیه client-rendered بود؛ خروجی محتواییِ پیش‌رندرشده از ابتدا در فایل وجود نداشت. ساختار اصلی و متادیتا حفظ شده‌اند.

## آزمون مرورگر

```sh
npm ci --ignore-scripts
npx playwright install chromium
node tests/test_center_browser.cjs
node tests/test_local_preview.cjs
```

برای استفاده از Chromium نصب‌شده می‌توان متغیر غیرمحرمانهٔ `CHROMIUM_PATH` را تنظیم کرد. آزمون اول، مرورگر و سرویس Google را شبیه‌سازی می‌کند. آزمون دوم خود فایل نهایی را با `file://`، بدون اینترنت، در اندازه‌های موبایل و دسکتاپ باز و تعاملات اصلی را کنترل می‌کند. مسدودشدن file URL در سیاست مرورگر باید به‌عنوان مانع گزارش شود، نه موفقیت.

در محیط فعلی، سیاست مدیریت مرورگر `file://` را مسدود می‌کند؛ اما همین آزمون واقعی در runner گیت‌هاب برای موبایل و دسکتاپ با موفقیت اجرا شده است: [اجرای تأییدشدهٔ CI](https://github.com/b-behrouz/app/actions/runs/40330517087). این نتیجه، آزمون واقعی فایل آفلاین است و از آزمون HTTPS شبیه‌سازی‌شده جداست. جزئیات و شناسهٔ artifact در `docs/STATUS.md` آمده است.

## اتصال Google Sheets

[کد، تنظیمات و راهنمای اتصال](google-sheets/راهنمای-اتصال.md) در `google-sheets/` موجود است. آدرس `/exec` تنظیم نشده و اتصال زنده هنوز فعال نیست. انتشار با حساب دارای دسترسی ویرایش و آزمون واقعی لازم است. برای فایل محلی، تنظیم صریح `ALLOW_LOCAL_PREVIEW=true` در Script Properties نیز لازم است.

برای ساخت نسخهٔ شخصی بدون تغییر فایل‌های عمومی:

```sh
# config/preview.local.json را از نمونهٔ بدون رمز بسازید و فقط URL عمومی /exec را وارد کنید.
python3 scripts/build_preview.py --config config/preview.local.json --output work/hamghadam-preview.html
```

فایل تنظیم محلی و خروجی `work/` در `.gitignore` هستند. کلید، رمز، توکن یا دادهٔ درخواست کاربران را در سورس یا گیت قرار ندهید.

## ثبت خودکار درخواست‌ها

```sh
python3 scripts/setup_git.py
python3 scripts/finish_request.py --message "توضیح تغییر درخواست" --paths src scripts README.md
```

مسیرها باید دقیقاً متعلق به همان درخواست باشند؛ مثال را متناسب با درخواست تغییر دهید. اسکریپت ساخت و کنترل‌ها، آزمون سرور، بررسی staged source، commit، push بدون force و تطبیق SHA در مقصد را انجام می‌دهد. `--browser` آزمون اتصال شبیه‌سازی‌شده را هم اجرا می‌کند. hook محلیِ نصب‌شده، فایل‌های staged را از نظر الگوهای اسرار و سازگاری HTML با سورس کنترل می‌کند. این hook در clone جدید به اجرای `setup_git.py` نیاز دارد.

این ابزار یک روند اجرایی واقعی است، ولی daemon یا ناظر دائمی پیام‌های چت نیست؛ عامل باید آن را در پایان هر درخواست اجرا کند. مجوز کاربر برای این روند در `AGENTS.md` ثبت شده است. دسترسی GitHub و شبکه باید در نشست بعدی هم برقرار باشد. در شکست push، commit محلی باقی می‌ماند و موفقیت اعلام نمی‌شود.

`.github/workflows/verify.yml` پس از push، درخواست ادغام یا اجرای دستی، بررسی‌ها و آزمون‌ها را اجرا و در صورت موفقیت HTML را به‌عنوان artifact ذخیره می‌کند. این workflow سایت منتشر نمی‌کند و سورس را commit/push نمی‌کند. artifact گیت‌هاب نیز جای پیوست مستقیم HTML در چت نیست.
